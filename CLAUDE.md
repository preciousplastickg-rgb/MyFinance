# Личные финансы и дела — PWA для iPhone

Спецификация: `docs/SPEC.md`. Макет экранов: `docs/design/*.png`.
При расхождении макета и SPEC прав SPEC — но спроси, прежде чем менять поведение.

## Как работаем

- Один этап из раздела 10 SPEC = одна сессия. Не начинай следующий этап, пока я не проверил текущий на iPhone.
- В начале сессии скажи, какой этап делаешь и что войдёт. В конце — что проверить руками на телефоне.
- Конец этапа: `npm test` зелёный, Playwright smoke проходит, коммит «Этап N: …».

## Правила кода

- Стек фиксирован (раздел 2 SPEC): Vite + React 18 + TypeScript strict, Dexie, Tailwind, lucide-react, vite-plugin-pwa, zod, Vitest, Playwright.
- Новую зависимость не добавлять без причины, названной в коммите.
- Деньги — целые числа в минимальных единицах (×100), курс — целое ×10 000. Никаких float в расчётах.
- Даты операций — `YYYY-MM-DD` в Asia/Bishkek.
- Расчёты (баланс, лимит на день, курс, наступления регулярных платежей, отчёты, статистика дел) — чистые функции в `src/domain/` с тестами Vitest. UI только вызывает их.
- Контрольный пример лимита из SPEC 4.4 (1 850 / 1 210) — обязательный unit-тест.
- Любое изменение схемы Dexie — новая версия с миграцией и тестом на данных прошлой версии. Ничего не удалять из старых данных.
- Никаких `window.alert` / `window.confirm` — свои bottom sheet и диалоги.
- Все зоны нажатия ≥ 44×44, у кнопок-значков `aria-label`.
- Интерфейс на русском: «17 500 сом», «87,50».

## Dev

- `npm run dev` — разработка, `npm run build` — сборка, `npm test` — тесты.
- `npm run seed` (только dev) — тестовые данные за 3 месяца: счета MBank, О!Банк, Оптима, Наличные, USDT; 2 источника дохода, один в USDT; аренда, интернет, связь, 4 подписки.
