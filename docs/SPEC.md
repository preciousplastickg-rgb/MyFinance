# ТЗ: личные финансы и дела — PWA для iPhone

4 ноября 2026 · Нур

## 1. Цель и рамки

Личное приложение одного пользователя на iPhone: учёт денег (доходы в сомах и USDT, расходы, переводы между счетами, регулярные платежи) и планировщик дел, с отчётами «куда уходят деньги» и «что сделано». Работает полностью офлайн: без сервера, аккаунтов и синхронизации.

Главный критерий успеха — ввод траты за 3 тапа после открытия. Если ввод медленный, приложение забросят, какими бы ни были отчёты.

| Фаза | Что входит |
| --- | --- |
| 1 — Деньги | Счета, категории со значками, быстрый ввод, история, переводы и USDT, регулярные платежи и доходы, экран «Сегодня» с лимитом на день, отчёты, бэкап |
| 2 — Дела | Задачи, сферы, списки Сегодня / Предстоящие / Без даты, статистика, блок дел на «Сегодня» |
| 2b — Привычки | Привычки четырёх типов, блок привычек на «Сегодня». Тренировки (зал, бассейн) были в этапе 10 и убраны в этапе 13 |
| 3 — потом | Импорт банковских выписок из файла, лимиты по категориям, экспорт задачи в Календарь iPhone (.ics) |

Не делаем: сервер, синхронизацию, нескольких пользователей, push-уведомления, онлайн-курсы, трейдинг и P&L, подзадачи, проекты, канбан, теги.

Макет экранов — PNG в `docs/design/`, сверяться с ними. Этот документ лежит в репозитории как `docs/SPEC.md`.

## 2. Платформа и стек

PWA, которая ставится на iPhone через Safari → «Поделиться» → «На экран Домой» и после установки работает без сети.

| Слой | Решение |
| --- | --- |
| Сборка | Vite + React 18 + TypeScript (strict) |
| PWA | vite-plugin-pwa (Workbox): precache всех ассетов, manifest с `display: standalone`, иконки 180×180 и 512×512. Обновление по запросу: новая версия проверяется при запуске, при возврате в приложение и раз в 30 минут; если она есть — сверху плашка «Доступна новая версия · Обновить · ✕», «Обновить» перезагружает приложение без закрытия, «✕» откладывает до следующего открытия |
| Хранение | IndexedDB через Dexie.js; схема версионируется через `db.version(n)`, миграции только недеструктивные |
| Валидация | zod для импорта бэкапа |
| Стили | Tailwind CSS + CSS-переменные для темы (светлая / тёмная / системная) |
| Значки | lucide-react, отобранный набор около 60 значков, импортируются статически |
| Графики | Свой SVG (кольцевая диаграмма, столбцы), без библиотек |
| Шрифт | IBM Plex Sans, self-host, кириллица, 400/500/600/700 |
| Тесты | Vitest (логика), Playwright WebKit с эмуляцией iPhone 13 (smoke) |
| Хостинг | Статический: GitHub Pages или Cloudflare Pages, HTTPS обязателен для service worker |

Правила:

- Деньги хранить целыми числами в минимальных единицах: сом × 100, USDT × 100. Курс — целое число × 10 000 (сом за 1 USDT). Никаких float в расчётах.
- Дата операции — строка `YYYY-MM-DD` в часовом поясе Asia/Bishkek, плюс `createdAt` и `updatedAt` (timestamp).
- При первом запуске вызвать `navigator.storage.persist()`.
- Интерфейс на русском. Разделитель тысяч — пробел, десятичный — запятая: «17 500», «87,50». Валюта пишется «сом» и «USDT».
- Никаких `window.alert` и `window.confirm`: только свои bottom sheet и диалоги.

Ограничения iOS, которые принимаем: нет фоновых задач и уведомлений по времени без сервера, поэтому напоминаний нет — всё видно при открытии. Данные удаляются вместе с иконкой приложения, поэтому бэкап обязателен (раздел 8).

## 3. Модель данных

Балансы не хранятся, а всегда считаются из операций. Удаление счетов, категорий и сфер — только архивация (`archived: true`), чтобы история не ломалась.

```ts

type Minor = number;         // целое: сом×100 или USDT×100
type Currency = string;      // код: 'KGS' (база), 'USD', 'EUR', 'USDT', 'RUB', 'KZT', 'CNY', 'TRY', 'GBP' — раздел 4.6
type LocalDate = string;     // 'YYYY-MM-DD', Asia/Bishkek

interface Account {
  id: Id; name: string;               // 'MBank', 'О!Банк', 'Оптима', 'Наличные', 'USDT'
  type: 'bank' | 'cash' | 'crypto';
  currency: Currency;
  icon: string; color: string;        // имя значка lucide, hex
  includeInDaily: boolean;            // входит в лимит на день; KGS → true, USDT → false
  openingBalance: Minor; openingDate: LocalDate;
  sortOrder: number; archived: boolean;
}

interface Category {
  id: Id; name: string; kind: 'expense' | 'income';
  icon: string; color: string;
  isFixed: boolean;                   // обязательный расход (только expense)
  sortOrder: number; archived: boolean;
}

interface Transaction {
  id: Id;
  type: 'expense' | 'income' | 'transfer';
  date: LocalDate;
  accountId: Id; amount: Minor;       // amount > 0, в валюте счёта
  categoryId?: Id;                    // нет у transfer
  toAccountId?: Id; toAmount?: Minor; // только transfer; toAmount в валюте счёта-получателя
  rate?: number;                      // ×10000, сом за 1 единицу валюты; только перевод валюта ↔ сом
  note?: string;
  recurringId?: Id; dueDate?: LocalDate; // если создана из регулярного платежа
  createdAt: number; updatedAt: number;
}

interface Recurring {                 // регулярный платёж или источник дохода
  id: Id; kind: 'expense' | 'income';
  name: string;                       // 'Аренда квартиры', 'Зарплата 2 (USDT)'
  amount: Minor; currency: Currency;  // ожидаемая сумма
  accountId: Id; categoryId: Id;
  schedule:
    | { type: 'monthly'; day: number }               // 1..31, 31 в коротком месяце = последний день
    | { type: 'weekly'; weekday: number }            // 1 = пн
    | { type: 'yearly'; month: number; day: number };
  isMandatory: boolean;               // expense: резервируется в лимите на день
  isSubscription: boolean;            // для инсайта «Подписки»
  startDate: LocalDate; active: boolean;
}

interface OccurrenceLog {             // что сделано с конкретным наступлением
  id: Id; recurringId: Id; dueDate: LocalDate;
  status: 'done' | 'skipped'; transactionId?: Id;
}

interface Settings {                  // одна запись, key = 'main'
  rates?: Record<Currency, { rate: number; date: LocalDate }>; // последний курс каждой валюты, ×10000 сом за 1 (v3)
  lastUsdtRate?: number; lastUsdtRateDate?: LocalDate;        // до v3; при миграции копируется в rates.USDT
  smallExpenseThreshold: Minor;       // по умолчанию 300 сом
  theme: 'light' | 'dark' | 'system';
  lastBackupAt?: number;
}

// Фаза 2
interface Area { id: Id; name: string; icon: string; color: string; sortOrder: number; archived: boolean; }

interface Task {
  id: Id; title: string; areaId?: Id;
  icon?: string;                      // свой значок вместо значка сферы
  date?: LocalDate; time?: string;    // 'HH:mm'; без date = вкладка «Без даты»
  important: boolean; note?: string;
  repeat?: { type: 'daily' } | { type: 'weekly'; weekdays: number[] } | { type: 'monthly'; day: number };
  status: 'open' | 'done' | 'deleted';
  postponeCount: number;
  createdAt: number; doneAt?: number;
}

interface TaskEvent {                 // журнал для статистики
  id: Id; taskId: Id;
  type: 'created' | 'done' | 'undone' | 'postponed' | 'deleted';
  date: LocalDate;                    // день события
  fromDate?: LocalDate; toDate?: LocalDate; // для postponed
  at: number;
}
```

Индексы Dexie: `transactions: id, date, accountId, toAccountId, categoryId, recurringId, [type+date]`; `occurrenceLog: id, [recurringId+dueDate]`; `tasks: id, status, date, areaId`; `taskEvents: id, taskId, date, type`; v2: `habits: id, sortOrder`; `habitLogs: id, habitId, date, [habitId+date]`; `exercises: id, sortOrder`; `workouts: id, date, type`; `workoutSets: id, workoutId, exerciseId` (архив, см. выше). v3 и v4 индексов не меняют: v3 переносит курс USDT в `rates`, v4 переносит дни тренировок в отметки привычек.

## 4. Бизнес-логика

### 4.1 Баланс счёта

Баланс = `openingBalance` + доходы − расходы − исходящие переводы (`amount`) + входящие переводы (`toAmount`). Учитываются только операции с датой не раньше `openingDate` счёта: начальный остаток на эту дату их уже включает (у перевода каждая сторона — по дате остатка своего счёта). В отчётах и истории такие операции остаются. Отрицательный баланс разрешён, но подсвечивается оранжевым.

### 4.2 Переводы и USDT

- Перевод — не доход и не расход. Он не входит ни в отчёты, ни в итоги дня, ни в лимит как трата.
- Одна валюта (MBank → Наличные): `toAmount = amount`, поле «Зачислено» скрыто.
- Разные валюты (USDT → MBank или обратно): вводятся обе суммы, курс считается сам: `rate = сом / USDT`. Пример: 200 USDT → 17 500 сом = курс 87,50. Комиссия P2P уже сидит в курсе.
- После сохранения такого перевода обновляются `lastUsdtRate` и `lastUsdtRateDate`. Курс можно поправить вручную в настройках.
- Остаток USDT в сомах и общий итог по счетам считаются по `lastUsdtRate` и показываются с «≈» и датой курса. Курса нет — сумма в сомах не показывается.
- Доход в USDT в отчётах переводится в сомы по последнему курсу на дату дохода или раньше. Если такого нет — по первому более позднему. Сумма помечается «≈».
- Трата напрямую с USDT-счёта разрешена и переводится в сомы так же.

### 4.3 Регулярные платежи и доходы

- Наступления не хранятся, а генерируются на лету для окна [сегодня − 31 день; сегодня + 62 дня], но не раньше `startDate`. В `OccurrenceLog` пишется только исход: оплачено или пропущено.
- Платёж на «Сегодня»: кнопка «Оплачено» одним тапом создаёт расход с ожидаемой суммой, счётом и категорией, дата — сегодня, и пишет `OccurrenceLog(done)`. Долгий тап или «…» открывает sheet: поправить сумму и счёт перед сохранением или «Пропустить». После «Оплачено», «Пришло» и «Пропустить» — toast с «Отменить», как после быстрого ввода.
- Доход зачисляется сам в 17:00 по Бишкеку в день поступления (этап 15): операция с ожидаемой суммой на счёт источника, дата — день поступления, время записи — 17:00; `OccurrenceLog(done, auto)`. Приложение открыли позже — доход записывается задним числом тем же днём. До 17:00 на «Сегодня» строка «Сегодня в 17:00 зачислится само» с кнопкой «Уже пришло» (сумму и счёт можно поправить). Удалили автоматически записанную операцию — наступление становится «пропущено» и само больше не зачисляется. Автозачисление действует с дня обновления (`settings.autoIncomeSince`); более ранние неотмеченные доходы остаются карточками «пришло?» с «Да» и «Ещё нет». Счёт источника в архиве или в другой валюте — тоже карточка.
- Регулярный платёж или доход можно удалить в редакторе (с подтверждением, toast «Отменить»). Удалённый получает `deletedAt` и пропадает из списков, лимита и «Сегодня»; прошлые операции остаются в истории.
- Неоплаченное наступление с прошедшей датой висит оранжевым, пока его не отметят.
- Обычная запись, похожая на ожидаемое наступление (тот же вид, категория, валюта и сумма, срок не дальше недели вперёд), при сохранении спрашивает «Это оплата «Аренда квартиры»?». «Да» — запись получает `recurringId`, наступление отмечается `done`, лимит не вычитает платёж второй раз (как M и как S). «Нет» — обычная трата. Из нескольких подходящих берётся ближайшее по дате.
- Смена расписания у существующего регулярного показывает предупреждение: отметки привязаны к старым датам, прошлые наступления могут показаться просроченными.
- День 29–31 в коротком месяце сдвигается на последний день месяца.

### 4.4 Лимит на день («Можно тратить сегодня»)

- `D` — число дней от сегодня (включительно) до ближайшего ожидаемого поступления любого активного источника дохода (исключительно), не меньше 1. Источников нет — горизонт до конца месяца, с подписью об этом. Сегодняшнее поступление до 17:00 ещё впереди: в день зарплаты до 17:00 `D` = 1, подпись «до «Зарплата» (сегодня в 17:00)».
- `S` — потрачено сегодня: расходы с счетов `includeInDaily` с датой сегодня без `recurringId`.
- `B` — баланс на начало дня: сумма текущих балансов счетов `includeInDaily` + `S`.
- `M` — обязательные платежи: ожидаемые суммы неотмеченных наступлений `isMandatory` с датой до поступления, включая просроченные и сегодняшние, — только со счетов `includeInDaily`. Платёж со счёта вне лимита (например, подписка с USDT) лимит не уменьшает.

```
Лимит = floor((B − M) / (D × 10)) × 10
Осталось сегодня = Лимит − S
```

Контрольный пример (должен быть unit-тестом): сегодня 4 ноября, зарплата 10 ноября → D = 6. B = 27 600, M = 15 000 + 1 000 + 500 = 16 500. Лимит = 1 850. Потрачено 640 → осталось 1 210.

- Если B − M ≤ 0: вместо лимита оранжевый текст «До поступления не хватает N сом на обязательные платежи».
- Осталось сегодня < 0: прогресс-бар и число оранжевые, текст «Перерасход N».
- Под числом всегда расшифровка в две строки: «Свободно X на D дней до «источник» (дата)» и «B на счетах − M обязательных». USDT в лимит не входит (это сказано под списком счетов).

### 4.5 Умолчания для быстрого ввода

- 5 категорий на экране ввода — самые частые за 60 дней (при равенстве по `sortOrder`), шестая кнопка «Ещё…» открывает полный список.
- Счёт по умолчанию — последний использованный для этого типа операции. Дата по умолчанию — сегодня.
- Для перевода из USDT подставляется счёт-получатель последнего такого перевода.

### 4.6 Валюты

- Базовая валюта — сом. Счёт может быть в любой валюте из списка: KGS, USD, EUR, USDT, RUB, KZT, CNY, TRY, GBP; у всех два знака после запятой (×100).
- Всё, что в разделе 4.2 сказано про USDT, относится к любой валюте, кроме сома: курс — сом за 1 единицу ×10 000; обмен валюта ↔ сом обновляет `rates[валюта]`; курс правится вручную в настройках («Курсы валют»); итог по счетам, лимит и отчёты переводят валюту в сомы по курсу с «≈», без курса сумма в сомах не показывается.
- Перевод между двумя валютами без сома (USD → USDT) хранит обе суммы, курс в сомах не пишется; в форме показывается кросс-курс «1 USD = 0,9950 USDT».
- Валютные счета по умолчанию не входят в лимит на день (`includeInDaily: false`), включить можно в настройках счёта — тогда остаток переводится в сомы по курсу.
- На своей клавиатуре у сома кнопка «00», у остальных валют — десятичная запятая.
- Трата и доход в другой валюте (этап 16). Под суммой в форме — кнопка валюты («сом ▾»). Со счёта в сомах можно записать в любой валюте, с валютного — в его валюте или в сомах. Если валюта платежа не совпадает со счётом, строка «= 1 750 сом с MBank · курс 87,50 ✎»: курс подставляется последний (`rates[валюта]`), тап — поправить. Курса ещё нет — «Укажите курс USD», «Сохранить» открывает ввод курса. Со счёта списывается пересчитанная сумма до копейки; в операции хранятся `origAmount`, `origCurrency` и `rate`. Курс, введённый вручную, становится последним курсом валюты. В истории под суммой счёта мелко «20 USD».
- Трата с валютного счёта в его валюте хранит курс к сому (последний или поправленный): итоги месяца и отчёты считают её в сомах по этому курсу, точно, без «≈».

### 4.7 Долги (этап 17)

- `Debt`: направление «мне должны» (`owedToMe`) или «я должен» (`iOwe`), кто, валюта, начальная сумма без счёта (`opening`), дата, срок вернуть (необязательно), заметка, `closedAt`.
- Движение денег — операции `type: 'debt'` с `debtId` и `flow`: «мне должны» — дал в долг (out), вернули (in); «я должен» — взял (in), вернул (out). Они меняют баланс счёта, но не доход и не расход: в итоги месяца, итог дня, отчёты и лимит как трата не попадают.
- Остаток = начальная сумма + рост − возвраты. Погашен полностью или закрыт вручную («Закрыть без денег») — в «Закрытых». Срок прошёл — оранжевым «просрочен с …».
- Новый долг: «Дал в долг» / «Взял в долг», кто, сумма, счёт или «Без счёта» (тогда валюта выбирается, деньги по счетам не двигаются), когда, вернуть до, заметка.
- Карточка долга: остаток, «всего · вернули · срок», кнопки «Вернули» / «Дал ещё» (для «я должен» — «Вернул» / «Взял ещё»; сумма возврата по умолчанию — весь остаток, счёт — в валюте долга), история операций (тап — удалить операцию с «Отменить»), «Изменить», «Закрыть без денег» / «Открыть снова», «Удалить долг» (вместе с операциями, с «Отменить»).
- «Деньги»: строка «Долги · Мне должны N · я должен M ›» под итогами месяца. В истории операции долга: «Дал в долг · Азамат · MBank −5 000», тап открывает карточку долга.
- Схема Dexie v6: новая таблица `debts`; бэкап v6, файлы v5 открываются с пустыми долгами.
- Категория «Долг» в записи (этап 19): своя категория, в названии которой есть «долг» или «займ». «Сохранить» с ней открывает окно «Долг: 5 000 сом»: для расхода — «Дал в долг» / «Вернул долг», для дохода — «Взял в долг» / «Мне вернули»; кто — открытый долг в валюте счёта или новый человек: при «Дал / Взял в долг» — с «Вернуть до», при возврате — с «Всего долг» (пусто — равен сумме записи, долг сразу закрыт; меньше суммы нельзя), так возврат по долгу, которого в приложении ещё не было, заводит его сам. Долги в другой валюте перечислены подсказкой: вернуть их можно со счёта в той валюте. Запись становится операцией долга (не расход и не доход), новый человек — новым долгом; «Отменить» убирает и то и другое. Старые записи с этой категорией остаются расходами.

### 4.8 Копилка (этап 20)

- Копилка — отдельный счёт `type: 'savings'`: название, назначение (`purpose`: накопления, депозит, наличные, фонд — свой значок и цвет), валюта любая, «уже есть» (начальный остаток), цель и срок (`goal`, `goalDate`, необязательно). В лимит на день не входит (`includeInDaily: false`), счётом по умолчанию в записи не подставляется.
- Пополнить и снять — обычным переводом через форму записи: «Пополнить» открывает перевод «MBank → копилка» (счёт в валюте копилки, если есть), «Снять» — обратно. Разные валюты — курс посчитается сам, как у любого обмена.
- Прогресс: «25% из 100 000 · осталось 75 000 · по 18 750 в месяц до 15 марта» (месяцев до срока — по календарю, не меньше 1).
- Экран «Копилка» (из «Денег» и с «Сегодня»): «Всего накоплено ≈ N сом» и по валютам, список с полосками прогресса, «Новая копилка», архив. Карточка копилки: остаток, прогресс, «Пополнить» / «Снять», история, «Изменить копилку».
- В «Настройки → Счета» копилок нет — они живут в своём разделе. Бэкап v7: тип счёта `savings` и поля копилки; файлы v6 открываются как есть.

## 5. Экраны и UX

Нижнее меню из 5 позиций: Сегодня · Деньги · [+] · Дела · Отчёты. «+» — круглая тёмно-синяя кнопка 56 px по центру, открывает быстрый ввод денег. Настройки — значок справа в шапке «Сегодня». До фазы 2 вкладка «Дела» скрыта.

Между вкладками Сегодня → Деньги → Дела → Отчёты можно листать горизонтальным свайпом по любой части страницы, кроме строк со своим свайпом (история, задачи), полей ввода и ручек перетаскивания. Новая вкладка въезжает со стороны жеста; на краях — сопротивление.

Внутренние экраны («Регулярные», настройки, экран дня) закрываются свайпом вправо — как «‹ Назад». Вкладка под ними остаётся смонтированной: месяц в «Деньгах» и отчёте, поиск, вкладка «Дел» и прокрутка после «‹ Назад» те же, что были. Месяцы «Денег» и отчёта хранятся в навигации. Окна (bottom sheet) закрываются свайпом вниз за шапку или вправо по любому месту, кроме полей ввода и строк со своим свайпом. Жест в окне не листает вкладку под ним.

### 5.1 Сегодня

1. Шапка: день недели мелко и крупно дата («Четверг» / «5 ноября ▾») — без слова «Сегодня»; значок настроек. Тап по дате — календарь месяца (точка — в этот день были операции, сделанные дела или отметки привычек); выбранный день открывает «Итог дня»: расходы и доходы за день со списком операций и кнопкой «Запись на этот день», платежи этого дня со статусом (отметить, вернуть пропущенный), дела — сделанные и назначенные, привычки с отметкой задним числом (для будущих дней привычек нет). Дни листаются кнопками «‹ Предыдущий / Следующий ›».
2. Баннер бэкапа, если нужен (раздел 8).
3. Карточка лимита (тёмно-синий фон): «Можно тратить сегодня», число 48 px, прогресс «Потрачено / Осталось», строка с расшифровкой (4.4).

Порядок блоков ниже: «Счета», «Копилка», «Долги», «Платежи до поступления», «Дела», «Привычки» — выбор пользователя после проверки на телефоне.

4. Счета: по умолчанию свёрнуты до одной строки «Всего ≈ N сом» (под ней — число счетов и валюты без курса); тап по заголовку «Счета» раскрывает и сворачивает список, состояние запоминается. Раскрытые — все счета сразу, списком в одной карточке — значок, название, остаток справа; у валютных счетов значок с пунктиром, подпись «хранение» / «вне лимита» и «≈ N сом» под суммой. Последняя строка — «Всего ≈ N сом». Под списком: какие валюты не входят в лимит и курсы с датой. Тап по строке → история с фильтром по этому счёту.
5. «Платежи до поступления» с суммой справа: строка = значок категории в круге 36 px, название, «Завтра · 15 000 сом» (завтра и просрочено — оранжевым), кнопка «Оплачено» (контурная, чтобы не спорить с карточкой лимита). После нажатия — зелёная галочка «Записано», через 2 с строка уходит. Если счёт платежа в архиве или сменил валюту, «Оплачено» открывает окно выбора счёта, а не пишет на архивный. В том же блоке карточки ожидаемых доходов «Пришло?». Сумма в заголовке — все платежи; если обязательных меньше, под списком подпись «Из них обязательных N — они вычтены из лимита».
6. «Дела» (фаза 2): группы «Сегодня, 4 ноября» (просроченные + сегодня) и «Завтра, 5 ноября», всего не больше 6 задач. Если на завтра дел нет — до 6 сегодняшних; если есть на оба дня — по 3; если одному дню нужно меньше 3, свободные места отдаются другому. Внутри дня сначала важные, затем просроченные, затем по времени. Не поместившиеся — «· ещё N» в заголовке группы. Тап по задаче открывает её карточку. Ссылка «Все дела».

Заголовки блоков (Счета, Платежи до поступления, Дела, Привычки) — кнопки во всю ширину строки, чтобы их доставал большой палец и левой, и правой руки: «Счета» сворачивает и разворачивает список, «Платежи» ведут в «Регулярные», «Дела» — в задачи, «Привычки» — в привычки. Подпись справа («Все дела ›», «1 из 5 сегодня ›», сумма платежей) остаётся.

### 5.2 Быстрый ввод (полноэкранная модалка)

1. «Отмена» слева, заголовок «Новая запись».
2. Переключатель Расход / Доход / Перевод.
3. Сумма 52 px по центру: «−250» для расхода, «+» зелёным для дохода. Под ней валюта выбранного счёта.
4. Расход и доход: сетка категорий 3×2 (значок сверху, название снизу, выбранная — рамка и фон цвета категории). Перевод: «Откуда → Куда», при разных валютах — поле «Зачислено на MBank» и строка «Курс 87,50 сом за 1 USDT».
5. Чипы: счёт, дата (Сегодня / Вчера / выбрать), заметка — подписи 13 px, чтобы «Наличные» не резалось. Сумма показывается как набрана: «12,0» не схлопывается в «12».
6. Своя цифровая клавиатура 3×4: 1–9, 00, 0, ⌫, кнопки 52 px (на экране ниже 740 px — 44, чтобы строка «счёт · дата · комментарий» оставалась видна). Системную клавиатуру не вызывать. До 9 цифр, для USDT десятичная запятая вместо 00.
7. «Сохранить» 56 px (на невысоком экране 48), неактивна при нулевой сумме. Модалка закрывается после записи в базу; если запись не удалась — остаётся открытой с сообщением об ошибке. Затем toast «Кафе −250 сом · Отменить» держится 5 с.

Расход = 3 тапа после «+»: сумма → категория → «Сохранить».

### 5.3 Деньги (история)

- Шапка: заголовок, значок поиска, кнопка «Регулярные» (список и редактор регулярных платежей и источников дохода). Под шапкой переключатель месяца «‹ Ноябрь 2026 ›» — такой же, как в отчётах; вперёд листается до текущего месяца или до месяца самой поздней записи, если она в будущем.
- Карточка Доходы / Расходы за месяц (USDT отдельной строкой с «≈ сом»); тап открывает отчёт за этот же месяц. Под ней две плитки «Копилка» и «Долги» в одну строку.
- Поиск по категории, комментарию, сумме открывается значком в шапке. Фильтр по счёту: чипы «Все, MBank, О!Банк, Оптима, Наличные, USDT» с переносом по строкам.
- Список по дням, у дня итог без переводов. Строка: значок в круге, категория, «комментарий · счёт», сумма (расход чёрным с «−», доход зелёным с «+», перевод серым «200 → 17 500»).
- Тап → редактор в той же полноэкранной модалке, что и «Новая запись» (в bottom sheet форма с клавиатурой не помещалась). Свайп влево → удалить с toast «Отменить». Список виртуализирован. Toast'ов может быть несколько (до трёх друг над другом); без кнопки «Отменить» сообщение держится 3 с.
- В форме записи «Ещё…» → плитка «Новая»: редактор категории нужного типа (расход или доход); сохранённая категория сразу выбрана (этап 19).

### 5.4 Настройки

- Счета: создать, переименовать, порядок перетаскиванием, архив (счёт с ненулевым остатком — с подтверждением: он пропадёт из «Всего» и лимита), валюта, начальный остаток, «Учитывать в лимите на день».
- Категории и сферы: редактор как на макете — превью 72 px, название, тип, переключатель «Обязательный расход», 8 цветов, сетка значков 6 в ряд с поиском по русским ключевым словам.
- Курс USDT (ручная правка), порог мелких трат, тема, бэкап и импорт.

### 5.5 Первый запуск

Три шага, каждый можно пропустить: счета с остатками (предзаполнено: MBank, О!Банк, Оптима, Наличные, USDT), источники дохода с датами, регулярные платежи. Базовые категории создаются сразу: Продукты, Кафе, Транспорт, Жильё, Связь и интернет, Подписки, Здоровье, Одежда, Дом, Развлечения, Подарки, Комиссии, Прочее; доходы: Зарплата, Подработка, Другое.

## 6. Отчёты по деньгам

Период — календарный месяц, переключатель «‹ Октябрь 2026 ›», по умолчанию текущий. Все суммы в сомах, USDT переводится по 4.2. Переводы не учитываются. Сверху переключатель «Деньги / Дела».

| Блок | Что показывает | Правило |
| --- | --- | --- |
| Расходы по категориям | Кольцевая диаграмма 200 px, в центре сумма. Ниже легенда: значок в круге цвета категории, название, Δ к среднему, сумма | До 6 сегментов по убыванию, остальное в «Прочее» на диаграмме; в легенде — все категории |
| Δ к среднему | «+38%» рядом с категорией | Сравнение со средним за 3 предыдущих полных месяца. Для текущего, ещё не закончившегося месяца — со средним за те же числа (4 ноября — с 1–4 числом прошлых месяцев), с подписью об этом. Показывать при ≥ 2 месяцах данных и при Δ не меньше 10% по модулю; ≥ +20% — оранжевым |
| Детализация | Тап по категории → столбцы за 6 месяцев и список операций месяца | — |
| Обязательные и переменные | Одна составная полоса и две суммы с % | По `Category.isFixed` |
| Доходы | Сумма по источникам, USDT с «≈» | — |
| Где можно сократить | До 3 карточек, только сработавшие условия, по убыванию суммы | См. ниже |

Правила карточек «Где можно сократить»:

1. Рост категории: Δ ≥ +20% и сумма ≥ 1 000 сом. Текст: «5 600 сом в октябре при обычных 4 060 (среднее за 3 месяца). 22 покупки, средний чек 255».
2. Подписки: активные `Recurring` с `isSubscription`. Текст: «4 подписки, 800 сом в месяц = 9 600 в год», тап → список подписок.
3. Мелкие траты: расходы меньше `smallExpenseThreshold`, если их доля ≥ 10% расходов. Текст: «38 покупок, 6 100 сом — 14% всех расходов».

Пустое состояние: меньше 30 дней записей — диаграмма есть, сравнений и карточек нет, подпись «Сравнения появятся после месяца записей».

## 7. Планировщик дел (фаза 2)

Планировщик строится в том же коде после приёмки фазы 1. Каждая задача живёт в одном из трёх списков, без проектов и подзадач.

### 7.1 Экран «Дела»

- Поле добавления сверху и чипы «Сегодня · Завтра · Дата и время · Сфера» — чипы появляются, когда начали писать задачу (или дата/сфера уже отличаются от умолчания), чтобы пустая форма не дублировала вкладки. Enter добавляет задачу, поле остаётся в фокусе. Дата по умолчанию по текущей вкладке: Сегодня → сегодня, Предстоящие → завтра, Без даты → без даты.
- Вкладки «Сегодня · Предстоящие · Без даты · Выполненные», ширина по тексту в виде сегментированного переключателя, как «Задачи / Привычки»: выбранная — светлая на сером фоне, не тёмная, чтобы не путаться с чипом «Сегодня». В них только название. Счётчик — бейдж в правом верхнем углу кнопки, `position: absolute`, смещён на −9 px вверх и −3 px вправо, поверх края. Бейдж: высота 20 px, минимальная ширина 20 px, 11 px жирный, рамка 2 px цвета фона. Цвет бейджа «Сегодня» — оранжевый, только если есть просроченные задачи, иначе тёмно-синий, как и у остальных. 0 — бейдж скрыт, больше 99 — «99+». `aria-label` кнопки: «Сегодня, задач: 5».
- Сегодня: сначала группа «Просрочено» (открытые с датой раньше сегодня, заголовок оранжевый), затем сегодняшние: со временем по времени, без времени — в конце. Внизу строка «Сделано сегодня: N ›» — переход на «Выполненные».
- Выполненные (этап 15): все сделанные задачи по дню выполнения, новые дни сверху. Повторяющиеся задачи после выполнения остаются `open`, поэтому «Выполненные», «Сделано сегодня: N» и итог дня берут сделанное из журнала `TaskEvent(done)` без последующего `undone`; такая строка показывается сделанной, «Вернуть в работу» возвращает её на день отметки.
- Выполненная задача (этап 19): галочка — только отметка, тап по строке открывает просмотр «Выполнено» — когда сделана (дата и время), что было запланировано, повтор, сфера, заметка. Вернуть в работу — кнопкой «Вернуть в работу» в этом окне; случайный тап ничего не меняет. Выполнить — галочкой или свайпом вправо: зелёная плашка «Выполнено».
- Предстоящие: группы по датам на 30 дней вперёд («Завтра, 5 ноября», «Пятница, 6 ноября»), дальше — «Позже». Без даты: задачи, у которых не указана дата (идеи, дела «когда-нибудь»), новые сверху. Раньше вкладка называлась «Входящие» — переименована, потому что смысл названия был непонятен.
- Строка задачи: чекбокс 22 px в зоне нажатия 44×44; название; под ним «время · значок и название сферы · повтор»; флажок справа, если `important`. Оранжевая строка-предупреждение: «Перенесено N раз» при `postponeCount` ≥ 3, «Без даты уже N дней» при возрасте без даты ≥ 14 дней.
- Жесты: свайп вправо — выполнить; свайп влево — «Перенести» (Завтра / Следующий понедельник / Выбрать / Убрать дату) и «Удалить». Тап — карточка задачи.
- Карточка задачи (bottom sheet): название, дата, время, повтор, сфера, свой значок (по умолчанию значок сферы), «Важно», заметка, удалить.

### 7.2 Правила

- Перенос = смена даты открытой задачи на более позднюю или снятие даты: `postponeCount++` и `TaskEvent(postponed)`. Перенос на более раннюю дату не считается.
- Повторяющаяся задача: при выполнении пишется `TaskEvent(done)` с текущей `date`, затем `date` сдвигается на следующее наступление, `status` остаётся `open`, `postponeCount` обнуляется.
- Отмена выполнения — `TaskEvent(undone)`, доступна в toast 5 с и тапом по зачёркнутой задаче до конца дня.

### 7.3 Отчёты → Дела

- Период: неделя (пн–вс) или месяц, переключатель «Неделя / Месяц».
- Три плитки: Сделано (зелёным); Осталось для текущего периода или Перенесено для прошедшего; Просрочено (оранжевым).
- Столбцы по дням недели или неделям месяца: светлый столбец = запланировано, синий внутри = сделано, над столбцом «6/7», сегодня выделено жирным. Запланировано на день D = задачи, у которых в какой-то момент была дата D (считается по журналу `TaskEvent`), кроме удалённых. Сделано = события `done` с датой D без последующего `undone`.
- По сферам: полоски «Работа 8 из 10» цветом сферы со значком.
- «Откладывается»: задачи с `postponeCount` ≥ 3 или дольше 14 дней без даты, кнопки «Сделать сегодня» (или «Назначить дату») и «Удалить».
- Процент выполнения крупным числом не выводить: только «14 из 21» в заголовке графика.

## 7a. Привычки (фаза 2b)

Живут на экране «Дела»: переключатель «Задачи / Привычки» сверху. Нижнее меню не меняется.

### 7a.1 Привычки

Привычка — просто галочка за день: сделал или нет. Ни счётчиков «+1», ни подтверждений, ни причин (этап 14).

| Расписание | Пример | Серия |
| --- | --- | --- |
| Каждый день | Медитация, Вода «3 литра» | Дни подряд |
| По дням недели | Спортзал пн, ср, пт | Дни по расписанию подряд; остальные дни пропускаются |

- Подпись (необязательно) — текст для себя: «3 литра», «20 страниц». В расчётах не участвует.
- Карточка привычки: значок, название, расписание и подпись, серия; под ними неделя пн–вс из 7 квадратов. Тап по дню ставит или снимает галочку. Сегодня обведено; дни вне расписания бледные, но отметить их можно; будущие дни и дни до старта не нажимаются.
- Порядок привычек — перетаскиванием за ручку ⋮⋮ на «Дела → Привычки»; тот же порядок на «Сегодня».
- Тап по названию — sheet: текущая и лучшая серия, % за 30 дней, календарь за 12 недель (сверху текущая неделя, ниже — прошлые, подписи месяцев), правка, архив. Тап по дню в календаре тоже ставит или снимает галочку.
- Серия считается до вчера включительно, если сегодня ещё не отмечено: невыполненное «сегодня» серию не обрывает.
- % за 30 дней — галочки / дни по расписанию, не больше 100 %.
- «Сегодня»: блок «Привычки» с теми же карточками; «N из M сегодня» — по привычкам, которые ждём сегодня.

- «Отчёты → Привычки»: выполнение каждой привычки за 30 дней, текущая и лучшая серия.

Миграция на v5 (этап 14) ничего не удаляет: «N раз в неделю» получает дни (1 → пн; 2 → вт, чт; 3 → пн, ср, пт; 4 → пн, вт, чт, пт; 5 → пн–пт; 6 → пн–сб; 7 → каждый день); у «количества» цель уходит в подпись («8 стаканов»), а день засчитан, если за него набрана прежняя цель; у «дней без…» каждый день без срыва от старта до дня миграции получает галочку, а запись срыва остаётся со значением 0.

Тренировок (зал, бассейн) в приложении нет: убраны в этапе 13. При миграции на v4 дни тренировок у привычек, где было «Засчитывать тренировки», стали обычными отметками — серии и проценты не изменились. Сами записи тренировок остаются в базе и в бэкапе.

## 7b. Переходы: всё, что показывает число, открывает то, из чего оно сложилось (этап 18)

- «Сегодня» (этап 20): под «Счетами» — блоки «Копилка» и «Долги», устроенные как «Счета»: свёрнуты до строки итога («Всего накоплено ≈ N сом», «Все долги · мне N · я M»), тап по заголовку раскрывает список, состояние запоминается. Строка копилки — полоска прогресса и %, тап — карточка копилки. В свёрнутых «Долгах» всё равно видны просроченные и со сроком в ближайшие 7 дней, в заголовке справа «Ещё N» (сколько скрыто); тап по долгу — его карточка. Нет открытых долгов — блока нет; нет копилок — только заголовок «Копилка · Завести», без карточки.
- «Сегодня»: тап по низу карточки лимита — окно «Из чего лимит»: формула, счета в лимите (тап — история счёта), обязательные платежи до поступления (тап — «Регулярные»), траты сегодня (тап — правка), поступление (тап — «Регулярные»). Блок «Долги» — просроченные и со сроком в ближайшие 7 дней, тап — «Долги».
- «Деньги»: плитки «Доходы / Расходы» — отчёт по деньгам; заголовок дня в истории — итог этого дня.
- Отчёт по деньгам: операции в детализации категории открываются на правку, столбец месяца показывает операции того месяца; «Обязательные» и «Переменные» — их операции за месяц; строка дохода — её операции.
- Отчёт по делам: плитки «Сделано / Осталось (Перенесено) / Просрочено» и строки сфер открывают сами задачи (отметить, открыть, перенести); столбец недели — итог дня, столбец месяца — эта неделя по дням. Без задач за период вместо пустой диаграммы — «На этой неделе задач не было». Среднее по категории в отчёте по деньгам — до сома, без копеек.
- Отчёт по привычкам: строка — карточка привычки с календарём.
- Итог дня: сделанные задачи — тем же списком, что «Выполненные», галочкой можно вернуть.
- Нажимаемые столбцы графиков стоят вплотную, каждый не уже 44 px; горизонтальной прокрутки нет.
- Кольцо расходов (этап 20): при открытии и смене месяца сектора прорисовываются по кругу один за другим, итог в центре набегает от нуля. Тап по сектору — он толще, остальные бледнее, в центре «Кафе · 400 · 17% расходов»; палец ведут по кольцу — выбор идёт за пальцем («лупа»); тап по центру — детализация категории; повторный тап по сектору или тап вне диаграммы — снять выбор. Столбцы в отчётах (детализация категории, «Дела») вырастают слева направо при открытии и смене периода, плитки и проценты «Привычек» набегают от нуля, полоски наливаются. «Уменьшить движение» в iOS — без анимации.

## 8. Бэкап, экспорт, импорт

Данные есть только на телефоне, поэтому бэкап — часть MVP, а не дополнение.

- Экспорт JSON: файл `finance-backup-YYYY-MM-DD.json` с `schemaVersion`, `exportedAt` и всеми таблицами. Отдаётся через `navigator.share({ files })` — откроется меню iOS, дальше «Сохранить в Файлы» → iCloud Drive. Если Web Share с файлами недоступен — скачивание через ссылку и вопрос «Файл сохранился?»: бэкап считается сделанным (и импорт или удаление идут дальше) только после «Файл сохранён». После успеха обновляется `lastBackupAt`.
- Импорт JSON: выбор файла (`accept=".json"`), проверка через zod, превью «Счетов 5, операций 1 240, задач 86, бэкап от 2 ноября». Режим один — «Заменить всё». Перед заменой текущие данные автоматически экспортируются, замена идёт одной транзакцией Dexie. Файл старой `schemaVersion` прогоняется через те же миграции.
- Экспорт CSV операций для Excel: UTF-8 с BOM, разделитель `;`, колонки `дата;тип;сумма;валюта;счёт;категория;счёт_получатель;сумма_зачисления;курс;комментарий`, суммы с десятичной запятой.
- Баннер на «Сегодня»: если есть хотя бы 20 операций и бэкапа не было или он старше 7 дней: «Последний бэкап 9 дней назад» + кнопка «Сохранить». Закрыть можно на 24 часа.
- Удаление всех данных — в настройках, с подтверждением вводом слова «УДАЛИТЬ» и с автоэкспортом перед удалением.

## 9. Дизайн и нефункциональные требования

Все цвета — CSS-переменные, чтобы тёмная тема сводилась к замене значений. Чёрный фон не используется: тёмные поверхности тёмно-синие. Выбранная тема дублируется в `localStorage` и ставится inline-скриптом в `index.html` до загрузки приложения — без светлой вспышки при старте.

| Токен | Светлая тема | Где |
| --- | --- | --- |
| `--bg` | #F4F5F7 | Фон экрана |
| `--surface` | #FFFFFF | Карточки, списки, клавиатура |
| `--ink` | #15171A | Основной текст |
| `--muted` | #5B6170 | Подписи, неактивные вкладки |
| `--line` | #E4E6EB | Разделители, фон переключателей |
| `--primary` | #172554 | Карточка лимита, «+», «Сохранить», активный чип, бейджи |
| `--accent` | #2448D6 | Ссылки, активная вкладка меню, чекбокс |
| `--income` | #0B7A4B | Доходы, «Сделано» |
| `--warn` | #B45309 | Просрочено, перерасход, рост категории |
| `--crypto` | #0E7490 | USDT |

- Палитра категорий и сфер (8 цветов): #2448D6, #0B7A4B, #B45309, #6D3FC4, #0E7490, #BE185D, #172554, #5B6170. Фон кружка значка — цвет с прозрачностью 12% (`#RRGGBB1F`), сам значок — цвет 100%.
- Шрифт IBM Plex Sans, у сумм `font-variant-numeric: tabular-nums`. Размеры: лимит 48, сумма ввода 52, h1 28, h2 17, основной 15, подписи 13, меню 11.
- Радиусы — два токена: карточки, sheet, toast — 8 (`rounded-card`); поля, кнопки, чипы, клавиши, переключатели — 6 (`rounded-ctl`); бейджи 4, полосы прогресса 2. Круглые — только настоящие круги: значки в кругах, «+», чекбоксы задач, точки. Капсул нет.
- Отступы: поля страницы 16, между блоками 16, внутри карточек 16; поля ввода высотой 44. У привычки пропущенный день по расписанию — рамка и подложка цветом привычки, день вне расписания — бледный.
- Горизонтальных каруселей нет: чипы переносятся по строкам, счета — списком.
- Все зоны нажатия ≥ 44×44. Нижнее меню и нижние кнопки учитывают `env(safe-area-inset-bottom)`.
- Доступность: настоящие `<button>` и `<input>`, `aria-label` у кнопок-значков, контраст текста ≥ 4,5:1, цвет не единственный носитель смысла (у сумм есть знаки «+» и «−»).
- Скорость: холодный старт до 1,5 с на iPhone 12; сохранение операции до 100 мс; история и отчёты без лагов на 10 000 операций. Размер сборки до 400 КБ gzip без шрифта.
- Анимации до 200 мс, уважать `prefers-reduced-motion`. Короткая вибрация при сохранении на iOS не доступна из PWA, не делать.
